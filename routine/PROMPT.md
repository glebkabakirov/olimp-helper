# Проверка сайтов олимпиад (Claude routine, раз в 3 дня)

Ты обновляешь файл `data/updates.json` в ветке **`claude/updates`** этого репозитория. Android-приложение
«Олимп-хелпер» читает его оттуда и накладывает находки поверх Google-таблицы. **Саму таблицу не
редактируй.** Кроме `data/updates.json` ничего не меняй, в `main` не пушь.

## Шаги

1. Скачай таблицу и выведи строки со ссылками:
   ```bash
   curl -sL -o /tmp/table.xlsx "https://docs.google.com/spreadsheets/d/16wKSRx8b7BC8YQeT9ulPl3gHKJ7hHWq0/export?format=xlsx"
   python3 routine/read_table.py /tmp/table.xlsx > /tmp/table.json
   ```
   В каждой строке: «Олимпиада», «Этап», «Дата этапа», «Примечание / источник», «Ссылка на источник»,
   «Регистрация на этот этап», «Ссылка на регистрацию».

   Если `curl` до docs.google.com не проходит (сеть облачной среды ограничена), возьми актуальные значения
   ячеек через WebFetch по адресу
   `https://docs.google.com/spreadsheets/d/16wKSRx8b7BC8YQeT9ulPl3gHKJ7hHWq0/export?format=csv&gid=749938116`,
   а ссылки на сайты — из снимка `python3 routine/read_table.py app/src/main/assets/table.xlsx`.
   Сайты олимпиад открывай через WebFetch (и WebSearch, если ссылка устарела).
2. Прочитай находки прошлого запуска:
   ```bash
   git fetch origin claude/updates && git show origin/claude/updates:data/updates.json
   ```
3. Открой сайты **всех** олимпиад из таблицы: каждую уникальную ссылку из «Ссылка на источник» и
   «Ссылка на регистрацию» (их около 35), по 5–8 запросов WebFetch параллельно. Не ограничивайся строками
   «Не опубликовано»: у подтверждённых этапов тоже переносят даты, открывают и закрывают регистрацию.
   Если ссылка не открылась или устарела, поищи официальную страницу через WebSearch. Смотри только
   информатику и программирование, сезон 2026/27.
4. Сравни сайт с таблицей. Записывай находку, только если на официальном сайте есть **подтверждённая**
   информация, которой в таблице нет или которая с таблицей расходится:
   - появилась или поменялась дата этапа → поле `date`;
   - открылась, закрылась или объявлена регистрация → `registration` и, если известно окно, `registrationDates`;
   - на сайте есть этап, которого в таблице нет → `"kind": "new_stage"`.
5. Если таблица уже говорит то же, что сайт, находку не пиши, а старую убери. Файл каждый раз
   переписывается целиком и содержит только **актуальные отличия сайтов от текущей таблицы**.
6. Сохрани файл на свежей базе из `main` и запушь в `claude/updates` (ветка каждый раз пересоздаётся,
   поэтому `--force`). Если находок нет, всё равно обнови `generatedAt` и закоммить:
   ```bash
   git checkout -B claude/updates origin/main
   # записать data/updates.json
   git add data/updates.json
   git commit -m "Проверка сайтов: ГГГГ-ММ-ДД, находок: N"
   git push --force origin claude/updates
   ```
   Пулреквест не открывай.
7. В финальном ответе перечисли **каждую** олимпиаду таблицы одной строкой: сайт открылся или нет и что
   найдено (или «совпадает с таблицей»). Олимпиада без строки в отчёте значит, что проверка не закончена.

## Формат `data/updates.json`

```json
{
  "generatedAt": "2026-10-28T06:00:00+03:00",
  "items": [
    {
      "id": "lomonosov-final-date",
      "olympiad": "Ломоносов",
      "stage": "Заключительный",
      "kind": "update",
      "date": "15.03.2027",
      "summary": "На сайте появилась дата финала по информатике: 15.03.2027",
      "sourceUrl": "https://olymp.msu.ru/rus/event/11010/",
      "checkedAt": "2026-10-28"
    },
    {
      "id": "itmo-open-qual-registration",
      "olympiad": "Открытая олимпиада школьников (ИТМО)",
      "stage": "Отборочный",
      "kind": "update",
      "date": "01.11.2026 – 15.01.2027",
      "registration": "ОТКРЫТА",
      "registrationDates": "01.11.2026 – 10.01.2027, 23:59 МСК",
      "summary": "Объявлены сроки отборочного этапа и открыта регистрация",
      "sourceUrl": "https://olymp.itmo.ru/",
      "checkedAt": "2026-10-28"
    }
  ]
}
```

## Правила полей

- `olympiad` и `stage` копируй **точно** как в таблице (колонки «Олимпиада» и «Этап»), иначе приложение
  не найдёт строку. Для `new_stage` поле `stage` — название нового этапа.
- `kind`: `update` (поправка этапа), `new_stage` (этапа нет в таблице), `info` (важная заметка без новых дат).
- `id`: стабильный, латиницей, одинаковый между запусками для одной и той же находки.
- `date` и `registrationDates` пиши в формате таблицы: `дд.мм.гггг`, диапазон `дд.мм.гггг – дд.мм.гггг`,
  время `, ЧЧ:ММ МСК`, несколько дней `14.11.2026 или 19.11.2026`, разные классы
  `14.02.2027 (6–9); 28.03.2027 (10–11)`.
- В `date` пиши дни самих туров или этапа, а не окно регистрации: несколько туров через « и »
  (`08.11.2026 и 06.12.2026`), многодневный этап диапазоном. Окно регистрации — только в `registrationDates`.
- `registration`: одно из `ОТКРЫТА`, `ЗАКРЫТА`, `ОТКРОЕТСЯ дд.мм.гггг`, `НЕ ОБЪЯВЛЕНО`.
- Поля, которые не меняются, не указывай.
- `summary`: одно короткое предложение по-русски о том, что нашёл. `sourceUrl`: страница, где это написано.
  `checkedAt`: дата проверки `ГГГГ-ММ-ДД`.
- Сайт недоступен (403, капча, таймаут) или данные прошлого сезона: ничего не выдумывай, пропусти.
